# Помощник для аудитора — десктоп-мессенджер (Electron)

Помогает проверить **дополнительное задание** по `cross_platform_appimage_audit.md`.
(Для основной соцсети см. отдельный файл `audit_helper.md`.)

Каждый пункт сопровождается шагами проверки и ожидаемым результатом.

---

## 0. Подготовка

Сначала должен быть запущен бэкенд основного проекта:

```bash
docker compose up --build      # из корня репозитория, поднимает backend на :8080 и сайт на :3000
```

Затем запустить десктоп-приложение:

```bash
cd desktop
npm install
npm start
```

На экране логина поле **Backend server** по умолчанию `http://localhost:8080`
(меняется, если бэкенд на другом адресе — удобно при проверке из VM).

Демо-аккаунты (пароль у всех `password123`): `bob@demo.local`, `carol@demo.local`,
`dave@demo.local`. Можно также зарегистрировать новых через сайт.

> **Примечание для этой среды:** установлена переменная окружения
> `ELECTRON_RUN_AS_NODE=1`, из-за неё `npm start` падает. На обычной машине её нет.
> При необходимости выполнить перед запуском:
> `set ELECTRON_RUN_AS_NODE=` (Windows) / `unset ELECTRON_RUN_AS_NODE` (Linux/macOS).

### Сборка установщиков (кросс-платформенность)

```bash
npm run dist:win     # Windows (NSIS) — для установки в Windows-VM
npm run dist:linux   # Linux (AppImage)
npm run dist:mac     # macOS (dmg)
```

Результат — в `desktop/dist/`. Linux-таргет — именно **AppImage**.

> **Если собираете из-под Windows.** `electron-builder` создаёт симлинки, а Windows
> по умолчанию это запрещает — сборка падает с `Cannot create symbolic link` /
> `A required privilege is not held by the client`. Это ограничение ОС, а не
> проекта. Решения (любое одно):
>
> - включить **Режим разработчика** (Параметры → Система → Для разработчиков);
> - либо запустить сборку в консоли **от имени администратора**;
> - либо собрать в Docker — так надёжнее всего для AppImage:
>
> ```bash
> docker run --rm -v "$PWD:/project" -w /project \
>   electronuserland/builder:latest /bin/bash -lc "npx electron-builder --linux"
> ```
>
> **macOS (`dmg`) собирается только на macOS** — это требование Apple, кросс-сборка
> невозможна. Для проверки в macOS-VM собирайте установщик внутри самой VM.

## General

- **Сессии** — да: токен сессии сохраняется на диск (между запусками).
- **Поля логина** — Email, Password.
- **Эмодзи** — кнопка 😊 в поле ввода, набор эмодзи для вставки.

## Functional

- **Регистрация** → ссылка «Register on the website» открывает сайт в браузере
  (страница `/register`).
- **Логин** созданным пользователем — успешно, открывается окно мессенджера.
- **Неверный пароль/почта** → сообщение «Invalid email or password».
- **Закрыть и открыть приложение заново** → вход **автоматический** (сессия сохранена,
  логин повторно не запрашивается).
- **Logout, затем закрыть и открыть** → приложение снова **просит логин**
  (в том числе если логаут был сделан **без сети** — сохранённый токен стирается
  локально, а не только по ответу сервера).
- **Браузер (сайт) + десктоп, разные пользователи, подписаны друг на друга:**
  сообщение из браузера приходит на десктоп **в реальном времени**, и наоборот.
- **Чат между ними** работает без сбоев.
- **Logout пользователя в браузере** → на десктопе он автоматически становится
  **offline** (в реальном времени, серый индикатор).
- **Логин в браузере как подписчик десктоп-пользователя** → на десктопе он
  становится **online** в реальном времени (зелёный индикатор).
- **Потеря интернета** → жёлтый баннер «You are offline…», индикатор статуса «Offline».
- **Отправка сообщения офлайн** → предупреждение, отправка заблокирована
  (при этом просмотр истории переписок остаётся доступным).
- **Поиск интерактивный** — результаты фильтруются **по мере ввода**, без кнопки.
- **Поиск конкретного сообщения** в переписке → выдаёт ожидаемый результат.
- **Установка в Windows-VM / macOS-VM** → собранный установщик
  (`npm run dist:win` / `dist:mac`) ставится и приложение ведёт себя так же.

> **Как сымитировать офлайн** без физического отключения сети: остановить бэкенд
> `docker compose stop backend`. WebSocket отвалится → появится баннер, отправка
> заблокируется, кэшированные сообщения остаются видимыми. Вернуть:
> `docker compose start backend` — соединение восстановится автоматически.

## Bonus

- ✅ **Операторы поиска:** `-исключить` / `!исключить` (исключение), `~нечёткий`
  (нечёткое совпадение), и числовые операторы по числам внутри сообщений:
  `>5`, `<10`, `>=3`, `<=7`, `=4`, `!=2`. Несколько операторов комбинируются (И).
- Внешняя авторизация (GitHub/Google) — **не** реализована.

## Где что в коде

- `desktop/main.js` — главный процесс: окно, перенос токена сессии в запросы к
  бэкенду (renderer работает с origin `file://`, поэтому cookie проставляется
  вручную), нативные уведомления, открытие внешних ссылок. Токен кладётся только
  в запросы к выбранному бэкенду и хранится зашифрованным средствами ОС
  (`safeStorage`).
- `desktop/preload.js` — безопасный мост (`openExternal`, `notify`,
  `setBackend`, `clearSession`).
- `desktop/renderer/app.js` — логика: логин/логаут, контакты, presence,
  WebSocket-чат, эмодзи, офлайн-режим, интерактивный поиск с операторами.
- `desktop/package.json` — конфигурация `electron-builder` (win/mac/linux-AppImage).
- `desktop/build/icon.png` — иконка приложения (512×512), из неё
  `electron-builder` генерирует `.ico`/`.icns`.
