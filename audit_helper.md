# Помощник для аудитора — основная соцсеть

Помогает проверить **основное задание** по `audit.md`.
(Для десктоп-приложения см. отдельный файл `cross_platform_appimage_audit_helper.md`.)

Каждый пункт сопровождается шагами проверки и ожидаемым результатом.

---

## 0. Подготовка

Из корня репозитория:

```bash
docker compose up --build      # или ./build.sh  /  pwsh ./build.ps1
```

- Фронтенд: **http://localhost:3000**
- Бэкенд (API): **http://localhost:8080**

Остановить: `docker compose down`.

## Functional / структура

- **Разрешённые пакеты.** Открыть `backend/go.mod`: только `gorilla/websocket`,
  `golang-migrate`, `mattn/go-sqlite3`, `golang.org/x/crypto` (bcrypt),
  `google/uuid` + стандартная библиотека. ✅
- **Структура бэкенда.** `backend/server.go` + `backend/pkg/{db,models,handlers,middleware,session,ws,utils}`;
  миграции в `backend/pkg/db/migrations/sqlite/`. Совпадает с примером из задания. ✅
- **Структура фронтенда.** `frontend/app` (страницы), `frontend/components`, `frontend/lib`. ✅

## Backend / разделение ответственности

- **Server** — `backend/server.go` (точка входа: роутер, middleware, `http.ListenAndServe`).
- **App** — `pkg/handlers` + `pkg/middleware` + `pkg/ws` (логика обработки запросов).
- **Database** — `pkg/db` (соединение + миграции) и `pkg/models` (запросы).

## Database / SQLite + миграции

Войти в БД внутри контейнера (команда из аудита):

```bash
docker exec -it social-network-backend sqlite3 /app/data/social.db
sqlite> .tables          -- видны все таблицы
sqlite> SELECT version FROM schema_migrations;   -- 13 (все миграции применены)
sqlite> SELECT email FROM users;
# В конце каждоый команды обязательно ";"
```

- **SQLite используется** — да (`mattn/go-sqlite3`). ✅
- **Миграции применяются автоматически** при старте (см. лог контейнера
  `migrations applied, schema version: 13`). ✅
- **Клиент может писать/читать данные** — проверяется регистрацией и созданием постов ниже.

## Authentication

1. **Сессии** — да, cookie `session` (HttpOnly), таблица `sessions`.
2. **Поля формы регистрации** (`/register`): Email, Password, First Name,
   Last Name, Date of Birth, Avatar (необязательно), Nickname (необязательно),
   About Me (необязательно). ✅
3. **Регистрация пользователя** → запись появляется в БД (проверить `SELECT * FROM users;`).
4. **Логин** только что созданным пользователем — успешно.
5. **Логин с неверным паролем/почтой** → ошибка «invalid email or password».
6. **Повторная регистрация того же email** → ошибка «account with this email already exists».
7. **Два браузера:** залогиниться в одном, обновить второй (не залогиненный) —
   второй остаётся гостем (редирект на `/login`).
8. **Два браузера, разные пользователи:** после обновления каждый остаётся под своим.

## Followers

- **Подписка на приватного** (`carol`) от другого пользователя → отправляется
  запрос (кнопка «Request to follow»), у carol появляется уведомление и
  возможность Accept/Decline на странице **Notifications**.
- **Подписка на публичного** (`bob`/`dave`) → подписка сразу, без запроса.
- **Два приватных пользователя:** один подписывается на другого → получатель
  принимает/отклоняет.
- **Отписка** — кнопка «Unfollow» (с поп-апом подтверждения).

## Profile

- Открыть свой профиль (`/profile/<свой id>`): видны все поля регистрации **кроме пароля**,
  все свои посты, списки подписчиков и подписок.
- Переключатель **public/private** (кнопка «Make private/public» с поп-апом).
- Приватный профиль виден **только подписчикам**; не-подписчик видит сообщение
  «This profile is private».
- Публичный профиль виден всем.

## Posts

- Создать пост: можно приложить изображение (JPG/PNG/GIF).
- Создать комментарий: тоже с изображением.
- Уровни приватности: **public**, **almost private** (только подписчики),
  **private** (выбрать конкретных пользователей в списке).

## Groups

- Создать группу (title + description).
- Пригласить подписчика → у него уведомление + Accept/Decline.
- Запрос на вступление → у создателя группы уведомление + Accept/Decline.
- Член группы (не создатель) может приглашать и запрашивать вступление.
- Внутри группы: посты и комментарии (видны только членам).
- **Событие**: запрашиваются Title, Description, Day/Time и две опции
  (Going / Not going); другие участники голосуют.

## Chat

- Два браузера, пользователи подписаны друг на друга → личные сообщения
  приходят **в реальном времени**.
- Два пользователя **без взаимных подписок** → чат создать нельзя
  (ошибка «You can only message users you follow or who follow you»).
- Три браузера → личное сообщение получает **только** адресат.
- Общий чат группы → сообщение в реальном времени получают все члены.
- **Эмодзи** — кнопка 😊 в поле ввода.
- Сервер не падает (есть middleware recover).

## Notifications

- Колокольчик/счётчик виден на **каждой странице** (в навбаре);
  непрочитанные сообщения показываются **отдельным** счётчиком на ссылке «Chat».
- Уведомления приходят при: запросе подписки (приватный профиль), приглашении в
  группу, запросе на вступление в группу (создателю), создании события (членам).
